# Trebell Code 2.0.0

Version 2.0.0 is the first major Trebell Code release since 1.6.0. It centers on the agent harnesses you run inside Trebell: Muse Code joins Claude Code, Codex, OpenCode, Cursor, Grok Build, Antigravity and Trebell Native, OpenCode 2 is supported, and each harness now brings its own models, approvals, sign-in and updates.

Since v1.6.0, 1,379 commits have landed. Besides the harness work, they redesign the interface, show what each turn did and how it ended, help Trebell Native through long tasks and network drops, and lower the app's CPU, memory and disk use. A few changes need a step from you when you update; they are listed under Changed and removed.

## Highlights

- **Muse Code is a new harness.** Choose it in Settings or the composer and sign in with `muse login`. Its replies, reasoning, commands and file edits stream into the thread, its approvals and questions come to Trebell's own card and dialog, and Usage shows its 5-hour and Weekly windows.
- **OpenCode 2 is supported** beside OpenCode 1.x, with turns that survive a dropped event stream and questions in Trebell's dialog.
- **Each harness brings its own models.** The picker shows each harness's own model list, options and default, a reopened thread resumes on the model it was using, and a harness's thinking shows as a collapsed Thinking row.
- **A redesigned interface.** One design covers the whole app, with the Inter and JetBrains Mono fonts and the same top bar on every page. Replies render as GitHub-style Markdown, with tables and code blocks you can copy.
- **Every turn shows what it did.** Each turn keeps its own activity card that says what each step did, such as a command's exit code and duration or an edit's diff. A turn that failed or was stopped before it replied ends with a row saying how and why.
- **Trebell Native streams, sees images and waits out network drops.** On OpenAI, replies stream in as they are written, except on code-change turns, which Native checks before it answers. Native can look at images in the workspace, waits for the network instead of failing the turn, and keeps your toolchain variables for the builds it runs.
- **Harness updates from Settings.** Update appears when a newer release exists, and Trebell updates each harness through whatever installed it or, for an install it does not update, names the command that does.
- **Lighter on your machine.** Trebell starts fewer background processes, uses less CPU and GPU while you type and replies stream, and opens large threads with much less disk and database work.

## Changed and removed

- **Codex runs the Codex CLI you have installed:** the first `codex` on your PATH, or the one in npm's global folder, instead of a copy built into the app. Without one, starting Codex says that Codex is not installed. Each Codex app server now starts with a random token of its own (see Security and privacy), and a Codex too old for that stops with a note to update it: `npm install -g @openai/codex`.
- **Freebuff is removed, and OpenAI is the default Native provider.** A saved Freebuff selection switches to OpenAI, and Freebuff model choices and Freebuff custom models are removed. Freebuff threads move to your current Native provider with their model cleared, so nothing from them is sent until you pick a model, and Freebuff's leftover sign-in data in Trebell's home folder is deleted. `trebell login`, `signup` and `logout` now say that Trebell has no sign-in of its own, instead of passing the command on to Codex.
- **Antigravity signs in with a Gemini API key** from Google AI Studio, typed in Settings; Google account sign-in is not offered. Antigravity runs in a home of Trebell's own, so a Google login, key or project from `~/.gemini` or another app is not used. Your global skills are linked in.
- **A send while the harness connection is down keeps your draft** and shows that Trebell is reconnecting. It no longer falls back to the Native API provider, which would bill your OpenAI key.
- **Fewer approvals for reads.** In Supervised and Auto-accept edits, Native reads, lists and searches inside the project without asking; a path that leads outside the project still asks. Cursor, Grok Build and Antigravity read and search files without asking in every mode, Read only included (in Grok Build's Auto mode, whatever Grok asks about still comes to you). Writes, commands and other actions still follow the mode.

## Harnesses

- Each harness supplies its own model list, model options and default model. A reopened thread resumes on the model it was using, and a model list that arrives later updates the open composer.
- Switching harness keeps your draft and clears the previous harness's model. Nothing is sent until the new harness's models are ready, and the old harness's approvals, Git text and errors do not carry over. While the open thread's turn runs, a switch asks first, and the task keeps running in its own harness; a switch, a profile's Use or a thread open that would restart Codex under a running turn is refused, with the reason on the row you clicked.
- When the active harness is not Trebell Native, that harness writes your commit messages and pull request text, as a one-off, read-only request that runs no tools. The Source Control button names the harness that will write it.
- The thinking of Claude Code, Codex, OpenCode, Cursor, Grok Build and Antigravity shows as a collapsed Thinking row, which shows the latest line while thinking streams and keeps its place after a reload.
- Claude Code, OpenCode and the ACP harnesses (Cursor, Grok Build and Antigravity) get Trebell's working context in a closed block followed by your request, so cautious agents no longer refuse a plain request. After a compaction or a model change, an ACP harness is told again that it runs inside Trebell Code, and on which model.
- When Claude Code, OpenCode, Cursor, Grok Build or Antigravity no longer has a thread's conversation, the next message starts one fresh session, hands it the thread's earlier messages and says so in a quiet row.
- A send to a harness that has to start first waits for it, up to ten minutes, instead of being marked "Not sent" after one minute. Outside Codex, pending approvals and agent questions survive a page reload or a dropped connection and are asked again in the next window, and several questions wait in order.
- Sign-ins, sign-outs and upgrades you do in your own terminal show in Trebell at the next check, and a failed turn checks the harness again so its sign-in advice appears. A harness whose version check is slow or fails can still start chats; only a command that is really missing reads as not installed, and a CLI that hangs is checked once a minute.
- Claude Code, Codex, Cursor, Grok Build, OpenCode and Antigravity start with your proxy and toolchain variables, so a harness behind a corporate proxy reaches its API and the builds it runs find their tools. A value that holds a password or token passes only when the profile approves its name. On macOS, the app opened from the Dock or Finder gets your login shell's PATH and JAVA_HOME. These variables go to harnesses on this computer, not to SSH or WSL environments.
- Attached audio and video are no longer dropped: a harness that cannot take them gets their saved path.
- ACP harnesses no longer lose a reply, permission request or command that holds a Unicode line or paragraph separator, which left turns waiting forever. An update Trebell cannot handle is dropped, with one entry in the thread's Execution trace, instead of stopping the Trebell server, and command steps stream their output while they run.

## Harness updates in Settings

- Update appears when a newer release exists. Trebell updates each harness through whatever installed it: npm into that prefix, with the install script allowed, or the own updater of Claude Code, Codex, Grok Build or OpenCode. For a WinGet, Homebrew, pnpm or other install, Settings names the newer release, the file the profile runs and the command that updates it.
- Update also appears for a Claude Code, Codex or Grok Build in npm's prefix whose install never finished, such as the placeholder claude.exe a skipped install script leaves, and installs the recorded version again so the binary starts.
- The harness list no longer waits on npm's registry, and Trebell asks npm itself about npm installs, so Update is offered behind a proxy or with a private npm registry.
- OpenCode updates stay on the installed line: a 2.x install updates to the newest 2.x, also when a 3.x is npm's latest release.
- A Muse Code run by Meta's launcher can be updated from Settings on its own release channel, and Settings says when the version did not change or the update ran out of time.
- Updating a harness leaves the harness you are using, and its open thread, as they were. The row says Installing while the update runs, also after a reload, then shows how it went, and a second install is not started.

## Muse Code

- Muse Code is a new harness, chosen in Settings or the composer. Trebell finds Meta's install, shows its version and lists Muse's models with the Thinking levels each one offers; you sign in with `muse login` in a Trebell terminal. It runs only on this machine, not in WSL or SSH environments. New and resumed sessions get streamed replies, reasoning, commands, file edits, web search results, Stop, and steering of a running turn.
- Muse Code's approval requests show on Trebell's approval card with Muse's own choices, and its questions open in Trebell's question dialog. Full access runs Muse Code in its Unrestricted mode without its sandbox, Auto uses Muse's Auto review, and the other modes use Ask me. A thread whose mode changed, or whose Muse host died between turns, is relaunched and resumed.
- When Trebell declines a request itself (for its policy, a window that never answered, Stop, or a commit-text request), it sends Muse a plain Reject and saves no rule; a rule that keeps a command out is saved only when you click its button on the card. A read outside the workspace is asked on the card in every mode but Full access, and in Full access so are a workflow child's protected writes and requests of a kind Trebell does not know.
- Sessions get Trebell's repository tools and the MCP servers you save for Muse Code in Settings. A server Muse cannot reach does not fail the turn, and a Muse Code build that cannot take session MCP servers is refused with a note to update it.
- Subagents and workflow agents show as rows in the turn that launched them, and Muse's todo list shows as the turn's plan. A report from finished background work shows as a turn of its own, which a message you send takes over and Stop ends. Background commands such as dev servers keep their session until they end, and idle sessions close after ten minutes unless their work still runs.
- The composer's context meter works for Muse Code threads, and Usage counts each turn's tokens once, cached and reasoning tokens included, and shows Muse Code's 5-hour and Weekly windows with their reset times.
- Compact works and says when there is nothing to compact, and Fork starts a fresh Muse Code session on the same profile with the earlier messages handed over. Rewind is refused, because Muse Code cannot do it.
- A reached usage limit says when it resets, a signed-out turn says once to sign in with `muse login`, and Muse's own retries show on the turn's retry row. When Muse Code exits, Trebell ends the turn at once with its running tools marked failed, and on Linux and macOS stops the processes left in Muse's process group.
- A META_API_KEY in Trebell's own environment reaches Muse Code only when the profile approves that name, so Muse keeps using your `muse login` instead of billing per token on a key meant for something else. Muse's model list is read only when needed, so switching harness or saving a profile does not start its host.

## Claude Code

- Claude Code threads start on Windows: Trebell launches Claude Code's own executable instead of npm's claude.cmd shim, which failed at once with "spawn EINVAL".
- Profiles that run on Amazon Bedrock, Vertex AI, Microsoft Foundry or Claude Platform on AWS, or through a gateway or router (a custom ANTHROPIC_BASE_URL), read as ready and start chats instead of being told to run `claude auth login`. These provider settings go only to a Claude Code on this computer, not on SSH or WSL hosts.
- Requests Claude Code still sends on for a decision (its ask rules, its own safety checks, Plan mode, and Full access when an administrator turned bypass off) come to you with Claude's own reason, instead of being approved under Trebell's policy. A request Claude wants decided once offers only Deny and Allow once, and the card says which mode Claude Code is running in.
- A thread stays in the mode Claude Code actually opened in, so a follow-up does not restart it and end its background agents and shells. If Claude switched itself to Plan mode and cannot leave it while background work runs, a message refused for that reason says so, and Edit from here on it ends that work and gives the message back to send.
- Typing into a running turn that waits on a subagent moves the subagent to the background first. It keeps working, and its result arrives later in a turn of its own.
- Claude's to-do list, and the task list its Task tools keep, show as the thread's plan, updated as Claude and its subagents work through it and kept across a restart. The composer's context meter shows how full the context window is, and the auto-compaction cue works for Claude Code.
- A turn that fills its context says to run /compact or start a new thread instead of calling it a usage limit, and a real usage limit says when it resets. Claude Code's own notices, such as a hook dropping the prompt or a switch to the fallback model, show once as a finished row instead of as Claude's answer, and a failed compaction says why instead of reporting the thread compacted.
- Claude Code works where an administrator manages mcp.json: Trebell no longer passes the strict MCP flag that made Claude Code exit at startup there.
- Pressing Stop or closing the thread while Claude Code starts ends that prompt, instead of Claude Code starting anyway and running the turn. A resumed conversation whose MCP setup hangs reopens only once the hung process has exited.
- Importing a long Claude Code session brings in its latest 120 turns, ending where Claude Code would resume it. Replies given after a compaction in the middle of a turn are kept, and the compaction summary no longer shows as a message you sent.
- A sign-out shows at the next Refresh of the Usage card and the model list, and a status check that prints nothing no longer tells a signed-in person to sign in. Usage charges a turn that failed before sending a request of its own only its own cost.

## Codex

- On a Codex approval card, Allow session is now Allow commands this session or Allow edits this session. It answers every later command or file change in that thread until a turn runs in another permission mode, the thread unloads or its app server ends; before, Codex asked again for each new command. Network access, extra permissions and anything your own ask rules name (such as confirming git push) still ask every time.
- A file-change approval card lists the files the change adds, edits, moves or deletes, and path rules apply to every file the change touches, however many there are.
- Goals: the first message keeps your objective as you typed it, in its bubble, history and the thread's title, while Codex is asked to start working on it. /goal or /goal resume during a running turn stops that turn and starts the goal, and /goal clear or /goal pause stops only a turn the goal drives. A goal Codex stops working on is paused after 5 seconds, and a Codex without goal support keeps your objective in the composer and says so.
- Goals, continuity notes, repository evidence, verification steps and delegated tasks longer than 4,000 bytes reach Codex whole, as numbered pieces, instead of with their middle cut out.
- If Codex's app server dies, Trebell starts it again on a free port, so a second Trebell or a leftover app server no longer blocks Codex, and after three refused reconnects the composer says why and offers Retry. If one thread's app server dies, the window keeps following your other threads.
- Usage counts every model request in a Codex turn, not only the last one, and records turns that ran while every window was closed. A turn whose retries ran out on HTTP 429 says it hit a usage or rate limit and points to Usage, and the account check names ChatGPT plans as ChatGPT does now: Pro 200, Pro 100, Pro 500, Business and Business Premium.
- Conversation history lists only your own Codex sessions, named after your request, not the child-agent, review, guardian and compaction sessions Codex runs for itself. Threads in Codex sections created in another Codex client are listed under those sections.
- The Speed picker on a new Codex task shows Fast when your own Codex config runs Fast, and Trebell sends no tier unless you pick one.
- WSL and SSH Codex profiles sign in and check the account in the Codex home their app server actually uses, and a Codex executable typed for a WSL or SSH host is kept and used for that host's checks, sign-in and app server.

## OpenCode

- OpenCode 2 runs through its own client and protocol, beside OpenCode 1.x. On a cold start, Trebell waits for the selected model instead of switching to another provider's, and the model picker fills only once two reads of the catalog agree. OpenCode shows as ready only when a connected provider lists models, and its providers are read again on Refresh and after a sign-in.
- OpenCode 2 turns survive a dropped or silent event stream: Trebell reconnects, asks OpenCode whether the turn still runs, and asks again any questions and approvals it missed. If it cannot reconnect, the turn ends saying so, and OpenCode's run of it is stopped.
- OpenCode 2 questions open in the question dialog, and the turn goes on with your answers. A dismissed or unanswered question ends the turn saying so, and questions and approvals left over from before a restart are cancelled, so the next message is not stuck behind them.
- OpenCode servers start more reliably. A server that exits because another one holds OpenCode's shared database is started again on a new port, up to three times; OpenCode 2's first-run database conversion gets up to 30 seconds; a server that still fails names what it printed before it exited.
- An OpenCode 1.x server that Trebell starts for a profile that sets OPENCODE_SERVER_PASSWORD works for chats, the model list and commit text. When a profile's own server refuses Trebell, Settings says so and advises checking the server URL, or leaving it empty so Trebell starts OpenCode itself.
- OpenCode turns longer than five minutes no longer fail, and permission requests and questions from OpenCode's subagents are handled instead of holding the turn forever. A message sent while OpenCode works steers the running turn, and when a tool call is refused, OpenCode gets the reason and carries on.
- Provider retries show on the turn's retry row, with the model, the seconds until the retry and the provider's reason, and an OpenCode 2 turn stopped by a quota or rate limit says so and points to Usage.
- A screenshot pasted into an OpenCode 2 chat goes as a file OpenCode reads. File reads show as the file's lines or the folder's entries, and an idle OpenCode 2 thread keeps Trebell's repository tools.

## Cursor, Grok Build and Antigravity

- Cursor is looked for at its official install location first, so an unrelated cursor-agent on PATH no longer stops it from starting. A turn that ends in Cursor's lost-connection error shows as failed, with what Cursor wrote before the error kept as its reply.
- Grok Build and Cursor sessions that need a sign-in sign in once with the harness's own method and carry on, so a Grok Build profile with only XAI_API_KEY runs turns. Grok Build's checks run with its updater off, so on Windows, Settings no longer opens npm console windows or replaces the Grok Build binary.
- Antigravity's Gemini API key is kept in an owner-only file outside settings.json and never shown again; the Antigravity row then says a key is saved and offers Change key. Saving a different key, or removing it, stops the Antigravity chats on this machine that use the old key and says how many were stopped.
- Antigravity installs only a download whose SHA-256 matches the one the ACP registry lists. It checks first that the drive has room for the whole install and names how much is needed, and a refused install leaves the current runtime unchanged.
- On networks where IPv6 is offered but does not route, reading the ACP registry and downloading Antigravity work, because each address now gets a second to connect. Antigravity failures say why in plain words, such as a sign-in with the key that Google did not answer within 5 minutes (most likely a broken IPv6) or a key whose account needs a subscription that includes Antigravity.
- Antigravity chats take attached audio as audio, BMP, JPEG, PNG and WebP images as images, and text and PDFs as embedded content, up to 50 MiB a message. Its multiple-choice questions show only their choices and Cancel.

## Trebell Native

- Native can look at PNG, JPEG and WebP images in the workspace, up to 8 MiB each, on local and remote environments. It checks that an image decodes before attaching it, and an image the provider cannot decode is taken out and the request sent again.
- When a model request cannot connect, Native waits for the network and tries again every 60 s until it gets through or you stop the turn, instead of failing after about two minutes. A request that got no answer is sent again after 2, 5, 15 and 30 s, and on a rate limit Native waits as long as the provider suggests. With OpenAI reasoning models, a dropped connection no longer loses the turn's reasoning.
- Commands Native runs keep your project's toolchain variables, such as GEM_HOME, BUNDLE_PATH, CARGO_HOME, RUSTUP_HOME, JAVA_HOME, GOPATH and VIRTUAL_ENV, locally and on remote hosts, so Ruby, Rust, Java, Go and Python builds find their tools. On Windows, they can run npm, npx, yarn and pnpm, which failed before with "spawn npm ENOENT".
- Code search also finds matches in docs, templates, configuration and changelogs. A search can be limited to a folder or a glob, results come back grouped by file, and the files that define a name are read before the files that only use it.
- Native can make up to 500 ordered replacements in a file in one step, applied all or none; a replacement that does not match says where the text nearly matches, and a successful edit's row shows its diff. A text file over the size limit is read in part, marked truncated, and git-ignored files inside the workspace, such as those under node_modules or build, can be read.
- On long tasks, runs of identical output lines are collapsed for the model, with the full output still retrievable. Background processes get short handles such as p1, also shown in the app, and a check on one shows only the output written since the last check and can wait for the process to finish. After the provider compacts the context, Native no longer leans on earlier output it can no longer see.
- Native recognizes more ways of asking for a code change, such as bug reports that quote code and requests like "build a...", "resolve..." or "drop support for...", and checks its work on those tasks. A limit such as "do not modify files outside X" no longer makes the whole task read-only.
- Native does less redundant work. It is asked to run independent checks together, starts with the repository's test commands and Git state, and makes one recovery pass instead of up to four. When its completion check cannot confirm the work, recovery stops and gives the reason, and Native keeps, or restores byte for byte, the version of the files the evidence best supports.
- Native's output limit per action is doubled to 65,536 tokens, so a long action is cut off and redone less often. When code Native has read repeats the same faulty logic for the same purpose, Native is now told to fix the cause there too, keeping the change focused.
- The model is told when you change the permission profile mid-thread, and a Read only thread answers a request for changes at once. A plain request in a checkout with uncommitted changes is answered as asked, and the model is told that Trebell does not restrict network access, so it may install a missing tool or library the task needs.
- On every provider, Native sends its working context in a closed block followed by your request, so a model no longer answers the repository context instead of your request, or refuses a plain request. Absolute paths inside the workspace are no longer joined to the workspace root twice, and GPT-5.5 and later models get the low text verbosity Codex uses.
- Stopping a turn that waits on an approval ends it at once, and a browser, desktop or delegation action never runs a second time after a window reloads or closes. In a multi-model fan-out thread, a follow-up goes to that thread's own model, which its picker shows.

## Native model providers and the model picker

- OpenAI's model list leaves out models that cannot run a Native turn (embedding, audio, image, realtime, Sora and search-only models, and models past their shutdown date), and the default is the newest full-size GPT model.
- The Thinking picker offers only the levels each OpenAI model accepts. GPT-6 point releases such as gpt-6.1-sol get the Thinking picker, Luna and Sol point releases also get Speed, and Gemini shows no Thinking picker until a model is chosen. A saved level that a model no longer accepts falls back to the provider default instead of failing the turn.
- On OpenAI, Native replies stream into the conversation as they are written. Code-change turns that Native checks before finishing, and other providers, still show the reply once it is complete.
- A refused API key shows the provider's own message, never a masked key or raw JSON, in Settings and beside the composer until a key is saved or removed, and a provider that cannot be reached or does not answer in time is named. A provider with no key shows "API key required" with Configure, which opens on the API key field.

## Conversation and turns

- Replies render as GitHub-style Markdown: lists, tables, links, and code blocks that show their language and have a Copy button. Wide tables and code scroll inside the reply.
- Each turn keeps its own activity card with its steps and failures, also after the next turn starts, a reload or reopening the thread. Rows say what each step did: a command shows its command line, exit code, folder and duration, a Native tool names the file or command it worked on, and a turn shows its verification result.
- A turn that failed or was stopped before it replied ends with a row saying how and why. A reply's heading names the harness, model and access mode the turn was sent with (after a reload, the harness alone), and the turn's last reply says how it ended, for example "done · 2.3s".
- A harness's own retry, such as Native waiting for the network or Codex reconnecting its stream, shows as one Retrying row that ends as "Recovered after retrying" or "Stopped while retrying", not as an error.
- Coming back to a thread whose turn is still running shows the reply from its start and in order, with the MCP progress and the diff that arrived while you were away. This works for Codex and ACP harnesses, also after a reconnect or reload.
- A context compaction shows as one row that goes from "Compacting context" to "Context compacted"; one that was stopped or failed is not labelled compacted.
- Edit from here asks once before it changes anything, refuses while a turn runs, and keeps any draft already in the composer. If the rewind is refused or fails partway, every file goes back as it was, line endings included. File checkpoints work in repositories where git has no user name or email set.
- A Stop pressed before the turn has started is kept, and the header reads "Stopping…" meanwhile. Escape dismisses an agent's question or cancels an app's request from anywhere in the dialog, without also stopping the turn.
- A double-click or a held key acts once on menus, approval, request and question buttons and keyboard shortcuts, so a second click no longer approves the next request unseen.
- A selection from one turn to another far down copies every turn in between. Diff lines wrap by default, with a remembered toggle to scroll instead, and code is shown without font ligatures.
- The conversation stays on its newest message when the window or terminal changes size, and keeps following its end when an approval card or a reply arrives just after you scrolled there.
- Multi-model runs and background sends say in plain words which models started, with their threads, and for a model that did not start, what failed and where its draft went.

## Composer, attachments and follow-ups

- When a send or a thread open does not go through, the reason shows beside the composer and your draft stays. What you type while a message is sending stays for your next message, the keyboard returns to the composer after a send, and a new task opened with Ctrl+N, the sidebar, the palette, History or Projects puts the keyboard in its composer.
- An unsent new-task draft and its mode survive a harness switch and New task.
- Picking a file from the @ menu replaces the whole word at the caret and keeps any punctuation after it; the chip says "Attaching…" until the file is in, and a message sent meanwhile waits for it. After Escape, typing / again reopens the slash menu once the draft has changed, and the @ menu stays shut while you only move the caret.
- A file over the size limit is refused at once, by name, while the other files upload, and Send waits until uploads finish. Files sent with a message, such as a pasted screenshot, show as chips under it, also after a reload, and Edit from here brings them back.
- A message whose attached file was removed after you attached it is refused by the file's name, with Attach it again, and the draft is kept. On every harness but Codex, an image attached to a thread in a WSL or SSH environment is refused with the reason: Trebell sends images to the agent only from this machine.
- The composer holds up in narrow windows and with many attachments: the attachment shelf grows upward and scrolls past three rows, long file names end in an ellipsis, and the menus and model picker open inside the window at any height of the terminal drawer.
- Follow-ups queued behind a turn you stopped stay queued, also after a reload or restart, until you send them or press Send now. A follow-up already on its way shows Sending, with Edit and Remove off, and on a harness that cannot steer a running turn, Send now says why it has to wait.
- Cite is offered for a triple-clicked last paragraph. Dictation says when the microphone is blocked, and a second click stops it.

## Threads, sidebar and history

- Move up and Move down reorder a thread within its section, and the order survives a restart. Archive, bulk actions and their Undo put threads back where they were, and opening a thread no longer moves it to the top.
- Bulk Pin, Settle, Archive and Snooze try every selected thread, and refused threads stay selected, with the reason. A refused thread action names the action and the thread, and a refused Undo names each thread it could not restore.
- Running threads show a pulsing dot. A thread list or History that cannot load says so and offers Retry, instead of showing no threads. Sidebar search matches thread titles, project names and linked pull requests.
- Opening a thread switches the sidebar and header at once; a slow open shows the thread's name with a spinner, and the thread opened last wins.
- The header shows the thread title whole wherever it fits, at any zoom or display scaling, and in narrow windows folds its actions into More actions.
- Keys typed right after Ctrl+K go into the command palette's search, and the palette finds threads beyond the loaded list. In the browser UI, Back and Forward move through Trebell's pages and threads.

## Goals, Runtime and Context

- /goal followed by an objective sets the thread's goal, and on Native threads /goal pause, resume and clear work as they do in Codex.
- The Goal panel keeps what you typed in the goal and notes until you save, through tab switches, reconnects and slow saves. If the saved goal changed elsewhere, it offers Use saved or Keep mine.
- The Runtime and Context tabs show only the open thread's or project's data, even when a slow answer for the one you left arrives, and background processes stay listed while the harness is disconnected.
- The Context Inspector shows search hits in docs and configuration files as text with the matching lines, instead of a "not indexed" error.

## Files, Git and pull requests

- The Files editor opens binary files as binary and never saves them as text. It asks before dropping unsaved edits, keeps them when you switch tabs or panels, and refuses to save over a file that changed on disk, offering Reload from disk or Overwrite.
- Saving keeps a Windows file's CRLF line endings, and Ctrl+S saves in the Files editor. Code files are coloured with their own language's grammar, including Go, Rust, Python, Java, C, shell and Dockerfiles, instead of JavaScript's, and plain text shows as text.
- The Diff tab shows new files git does not track yet, and staged changes beside unstaged ones, and a diff over 4 MB shows what fits. File names with spaces or non-ASCII letters show correctly, and long names are shortened in the middle.
- The Git panel shows how far the branch is ahead of or behind its upstream. It reads Changes again when the agent changes a file or ends its turn, and when the repository changes outside the thread.
- A refused commit, pull, push or other Git action shows git's reason as one plain reason, in English and without colour whatever your locale or config, and without the hint lines git prints for a terminal. Commit can finish a merge whose conflicts were resolved by keeping this branch's side.
- Merge and Auto-merge ask first, naming the pull request, the merge method and any failing or pending checks, and Publish asks Public, Private or Cancel. Auto-merge state and requested reviewers are shown, descriptions and comments are written in a multi-line box, and a merged pull request offers only the actions its host still allows.
- Each model of a multi-model send gets its own worktree reliably. Removing a worktree keeps uncommitted work that git would refuse to remove, and on Windows no longer empties the folders its junctions point to, such as another checkout's node_modules.

## Terminal, preview and project actions

- A bare Enter reaches the program, and a pasted block runs line by line. Long output, or a single very long line, no longer freezes the page; the screen keeps the last 5,000 lines and says when earlier output was dropped.
- A terminal you have scrolled up stays where you left it while output streams. Lines wrapped by the Windows console are no longer split with a repeated character, and side-by-side panes keep a usable width.
- If the terminal worker dies, open terminals say they stopped, and New opens a working terminal. A terminal whose connection drops reconnects by itself, and a paste or command sent meanwhile runs once it is back.
- Stopping, closing or quitting ends the programs a terminal or project action runs; on Windows this covers their whole process tree, after a short grace period.
- A project action runs as its terminal's own program, one run at a time, so a double-click no longer starts a second dev server. The header button shows the running action with a Stop that keeps its output, and the terminal shows the exit code when the action ends.
- In WSL environments, commands, hooks and sign-in terminals run through `wsl.exe --exec bash -lc`, so their dollar signs and backquotes reach bash as written.
- The preview's Back and Forward step through the pages it has shown, and an address where nothing answers says so instead of showing a blank frame.

## Browser panel and agent browser

- A Browser panel recording keeps going while you look at another tab or close the panel, with a red mark on the Browser tab. When the agent browser window closes, the recording stops by itself and is attached.
- The Browser panel comes back as you left it: the typed address, the previewed page, the inspected element and its note, and the zoom.
- The agent browser draws pages that set no background on white, so their text is readable for you and in the model's screenshot. javascript:, data: and about:blank popups are refused.
- A failed cookie or profile import shows the full reason, and profile names show whole.

## Projects, environments and editors

- Removing a project or a saved environment offers Undo, which brings back everything it had saved.
- Use for agent checks an SSH or WSL host first and refuses one that does not answer, and puts the previous environment back when the runtime cannot run on the new one. A switch back to Local machine always goes through.
- Cancelling a clone ends every process git started, so the cancel settles within seconds.
- Open in VS Code or Cursor shows the editor's window even when the editor was not running, and the editor stays open after Trebell quits.
- On the Projects and Environments pages, Save action, Save hook and Add environment act once per press and show Saving while they work, and a default changed for the open project applies to New task without a reload.
- A project icon must be a real PNG, JPEG, WebP or GIF image.

## Settings, Tools and Usage

- Shortcuts: a half-typed or misspelt shortcut is not saved, a key already used by another command is flagged, and the command palette, sidebar and tooltips show the keys you have set.
- Themes: VS Code theme files, with their comments and trailing commas, can be imported, and deleting a custom theme offers Undo.
- Settings search shows results in full and offers only cards that exist for the harness in use, and Settings reopens on the section you left.
- Saving is more reliable: an API key is sent and checked once per press, and a setting you saved stays saved when an older read lands after it. A storage retention below 1 day now means off, not the most aggressive cleanup.
- Removing a runtime profile, project action, MCP server, plugin share or lifecycle hook asks first. In the runtime profile editor, approved inherited environment variables can be typed one per line or separated by commas, and a refused Save profile says why inside the editor.
- Diagnostics, Tools, Usage and the license list say when they are still loading or could not load, with Retry, instead of claiming nothing is there. Tools actions on Codex plugins and marketplaces say what they are doing on their own button and keep going if you leave the page.
- Usage: an empty period says "No model usage in this period", a Grok Build period with nothing used shows a 0% meter with its reset, and Claude Code's Team and Enterprise monthly spend limits show as a Monthly spend row.
- SnapShots: Capture takes one SnapShot per press, and flipping one switch while another saves no longer turns the first one back. Setup's history import names each conversation it could not import, with the reason.

## Desktop app and window

- The window appears as soon as it has painted, at its saved zoom; before, it sometimes never showed. A second launch brings the running window forward, and on macOS, a Dock click while the first window is still being made no longer creates a hidden second window.
- Quit from the tray, Close and Restart & install work with a terminal open, instead of leaving the app running hidden. If the update installer does not start, the app comes back and offers Restart & install again.
- Failed update checks, downloads and desktop actions say why in plain words, instead of net:: codes, ENOENT or Electron's error prefix.
- Screen readers announce the window buttons as Minimize, Maximize and Close, and Maximize becomes Restore while the window is maximized. Ctrl+wheel zoom steps from the current zoom.
- At zoomed or scaled window sizes, the right panel docks inside the window or opens as an overlay drawer, instead of spilling past the right edge, and resize handles show only where they work.

## Look, layout and accessibility

- The interface is redesigned. One design covers the sidebar, conversation, composer, Settings, pages and inspector, using the Inter and JetBrains Mono fonts, and every page has the same top bar. Light mode opens without a dark first frame, and the docked inspector fits windows 900 to 1120 px wide.
- Every text question and confirmation uses Trebell's own dialog instead of the browser's, with Cancel focused. Focus goes back to the control that opened a dialog, a menu or the command palette.
- Small labels, helper text and dark primary buttons meet a 4.5:1 contrast ratio, and assistive technology announces the chosen Mode and Theme.

## Performance

- Trebell starts fewer processes. The terminal worker starts with the first terminal, Codex's catalog app server starts only when Codex is used, and the server loads each harness's SDK the first time it is needed: measured on a fresh start with Native active, it uses about 22 MB less memory and starts serving about 200 ms sooner.
- A harness session (OpenCode, Cursor, Grok Build, Antigravity) left idle for ten minutes is closed, and the next message resumes it; a session whose harness ran a command or another tool whose work can outlive the turn is kept until its thread closes. Reopening an OpenCode thread no longer starts OpenCode, moving between Settings' Agents & models and Diagnostics sections no longer starts an `opencode serve` for every OpenCode profile, and OpenCode threads start without waiting for OpenCode's command and skill lists. On Windows, an OpenCode found only through PATH, such as one installed with nvm-windows or into another npm prefix, now runs its own opencode.exe, so the servers Trebell Code started end with it even if Trebell Code is killed or crashes.
- CPU and GPU use is lower. A streaming reply re-parses only its unfinished part, and typing or a streaming reply restyles only what changed: on a 1,000-turn thread, the time from key press to drawn frame roughly halved. The Markdown renderer loads after the first paint, and nothing keeps animating while the app is idle.
- More of the app loads after the first paint, keeping the first screen's script under 200 KB gzip, and reloads and restarts reuse the cached UI files instead of downloading the whole bundle again.
- Large threads open and stream with much less disk and database work, and opening a short thread takes at most 5 requests.
- Background work is lighter. Git is checked every 3.5 s while the window has focus and every 30 s without it, a repeat check runs only git status, and the Git panel's first read of a repository starts 2 git processes instead of 7. Harness checks are reused for a minute, and idle timers fire only when there is something to release.

## Security and privacy

- The Files editor reads and saves only inside the project's folder, and links that lead outside it are refused, for pictures and other raw files too.
- Approval cards always show the exact command that will run. Allow once and Allow session apply only to the current session: nothing is written to a harness's project or user settings.
- Replies never run HTML or unsafe links: raw HTML stays as text, and only http(s) and mailto links are clickable, opening in the system browser. The desktop window only ever shows the app itself, and pull request, release, preview and plugin links open only if they are web or mail addresses, in a tab that cannot reach back into the app.
- Files previews of HTML, .htm and SVG files are sandboxed, and each PDF or HTML preview gets its own frame, so a workspace HTML file cannot run scripts with the app's origin.
- Each Codex app server Trebell starts requires a random token kept in an owner-only file, so no other program on the machine can connect to that Codex and drive it. Claude Code threads receive their MCP servers over stdin instead of on the command line, where other local users could read the environment values set for those servers.
- Tokens and keys that an API repeats in its error text are removed from Claude Code errors before they are shown, and in the ACP agent log lines that errors and warnings show, a Google sign-in page address is replaced by [sign-in-url].
- Commands Native runs do not get toolchain values that look like a password, secret, token, key, or login or connect-string credentials, nor JVM and build-tool option strings such as JAVA_TOOL_OPTIONS, MAVEN_OPTS and GRADLE_OPTS, where credentials can hide.
- Trebell does not read Claude Code's stored Claude.ai login, uses Antigravity's token file only to check that it exists, and reads Cursor's usage limits as Trebell instead of presenting itself as the Cursor CLI. The Cursor and Grok Build usage meters read those CLIs' stored sign-ins to ask the CLIs' own services, and the OpenCode Go meter reads the API key in OpenCode's auth.json.

## Install and update

- Windows x64: download and run `Trebell-Code-Setup-2.0.0.exe` from the releases repository, https://github.com/tanishqbaweja/trebellcode-releases.
- The installer is not signed, so Windows SmartScreen may ask you to confirm it before it runs (More info, then Run anyway).
- From 2.0.0 on, the in-app updater and Trebell's release check look for new versions in that repository; an update downloads and installs only when you choose to.
- If you use Codex or Antigravity, each needs a step of its own after you update: an installed Codex CLI recent enough for the app server's token, and a Gemini API key for Antigravity. See Changed and removed.
