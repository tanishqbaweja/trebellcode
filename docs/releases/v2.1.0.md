# Trebell Code 2.1.0

Version 2.1.0 lets Trebell Native run on xAI and the Meta Model API, and asks you which model to use when a provider names no default. You now choose in Settings how each harness signs in: with its own sign-in or with its vendor's API key. Attached documents now reach the other harnesses as text, Muse Code, Claude Code, OpenCode, Codex, Cursor, Grok Build and Antigravity get many fixes, and the window loads less before its first screen.

## Trebell Native

- **xAI and the Meta Model API.** Native can now run on xAI's API and on the Meta Model API. Add a key on the Model provider card in Settings: Trebell checks it against the provider's model list before keeping it, and the model picker lists only the models a turn can use, each with its Thinking levels. Each request carries the whole conversation, and a reply shows once it is complete, as on every provider but OpenAI.
- **You choose the model.** On a provider that names no default model, such as the Meta Model API, xAI and AgentRouter, the model picker reads Choose a model and lists every model your key gives, with the newest version of each model first. A message sent before you pick opens the picker and keeps your draft, instead of Trebell choosing a model for you. OpenAI still starts on gpt-6-luna, and a provider with a single model, a model saved for a thread or project, and the other harnesses pick as before.
- Until you pick a model on such a provider, Source control's Generate and Generate PR wait and say so, a project recipe that names no model asks for one and keeps its command, a background send asks for one and gives your draft back, and Settings says None (choose in the composer) instead of naming a model nobody chose.
- **One key for Native and the harnesses.** A key you save or remove on a harness's row in Settings is the key the Model provider card holds, so Trebell Native uses it too. The row says so, and when Native is active on that provider, its readiness and model list follow at once. A key the row reads from an environment variable shows as coming from that variable, not as saved.
- Native in the app and in Trebell's benchmark runs still read one shared configuration, so the Native you download is the Native the benchmarks run.

## Harnesses

- **Choose how each harness signs in.** In Settings, Agents & models, each harness and each of its runtime profiles can use **Sign in**, the harness's own login and the default, or **API key**, its vendor's key: Claude Code on the Anthropic key, Codex on the OpenAI key, Muse Code on the Meta Model API key, Grok Build on the xAI key, Antigravity on the Google Gemini key and OpenCode on each saved key of a provider it supports. Cursor signs in with its own login only. Trebell never reads or copies the sign-in a harness keeps for itself.
- **No key reaches a harness unless you choose it.** A key in `.env`, in Trebell's environment or in a profile's variables no longer reaches a harness set to Sign in. If a harness of yours ran on such a key, set it to API key on its row and save the key there. A harness on API key without a key says the key is missing and does not start. A harness runs on its key on this machine only: in a WSL or SSH environment, set it to Sign in to use its own login there.
- Changing a key or a sign-in method stops only the chats and Codex app servers of the profiles that use it, and says when open chats stopped; other profiles carry on. Removing a runtime profile stops its open chats too, and replacing or removing the OpenAI key signs out the Codex homes Trebell keeps for that key. A profile moved between Sign in and its API key never shows the other's models, account or plan usage.
- **Antigravity** can use its own sign-in, from Sign in on its row, or the Google Gemini API key, which it now shares with Trebell Native. A key saved in Antigravity's old key form moves to the Google Gemini key on the Model provider card, unless one is saved there already, and Antigravity stays on its API key. When the two keys differed, Antigravity's row says once which key is kept.
- **Usage.** The Cursor, Grok Build and OpenCode Go meters are gone, since they needed the sign-ins those harnesses keep for themselves; their cards now say that the harness does not report its usage to Trebell. The Claude Code card says when Claude Code is signed out and how to sign in again.
- **Attached documents as text.** Attach a Word, Excel or PowerPoint file, an OpenDocument text, spreadsheet or presentation, an RTF or EPUB file, or a Jupyter notebook, and Claude Code, Codex, OpenCode, Cursor, Grok Build, Antigravity and Muse Code now get its text instead of a file they could not read. Trebell extracts the text on your computer, in a separate process that never sees your API keys or tokens.
- **Muse Code: background work and compactions.** Workflows, agents, subagents and commands that Muse Code runs in the background stay on the card of the turn that started them, past that turn's end, a reload and your next messages, until they finish. A compaction takes as long as Muse needs, and Stop ends it, also while Muse Code is still starting; a stopped automatic compaction leaves the context as it was and sends your message on.
- **Muse Code: approvals, reports and failures.** Approval cards say what is asked: a write to a protected file, a read outside the workspace, another file access or network access. A staged command's card names the stage, and a workflow agent's card says which agent asks. While Muse Code writes its report, a message in another access mode is refused with your draft kept, and a queued follow-up stays queued and goes once the report ends. If Muse Code stops between turns, a card below the last reply says your next message starts it again; if it fails, Trebell says why once, in Muse Code's own words, and your next message goes as soon as Muse Code works again.
- **Claude Code.** A background task stays running on the card of the turn that started it until Claude Code finishes it, also after a reload. Claude's to-do lists show only as the turn's plan, without an Editing files step.
- **OpenCode.** OpenCode 2 rows are titled as OpenCode 1.x titles them, such as Run command, Read notes.txt or Asked 1 question, and a read opens to the file's lines or the folder's entries. An OpenCode 2 approval left unanswered ends its turn saying so, a message OpenCode 2 refuses while it still runs a turn stays as your draft with the reason, and a run OpenCode lost while Trebell reconnected reads as failed. On its API keys, OpenCode never falls back to a login made with `opencode auth login`. An OpenCode 1.x slash command names each attachment it cannot take as a file instead of dropping it.
- **Cursor, Grok Build and Antigravity.** When one of them stops as it starts, in a chat or while writing Git text, Trebell says so in plain words, naming the harness, its exit code and what it printed, instead of a raw runtime error. An Antigravity that asks for a Google sign-in points you to Sign in on its row, or to its key when it runs on one.
- **Codex.** A Codex app server in a WSL or SSH environment now needs a random token of its own, as on this machine, so another program that reaches its port cannot drive it; a Codex there too old for this says to update it. Variables that hold a key or sign-in stay off that host's command line. A goal Codex starts no next turn for is paused, also when the window is reloaded or closed or Trebell quits during the wait, and Resume in the Goal panel now starts the next turn, as /goal resume does.
- A turn that failed after writing part of its reply keeps that reply under its failed pill and says why, also after a reload, and a turn's error shows once, under its last reply, after you steer a message into it.
- A turn's context, verification and repair rows stay on that turn's card, also when the next turn starts at once, and a row that belongs to no turn, such as a refused send or a Muse Code compaction started with Compact, shows below the last reply in a card of its own.
- A call that never started reads as not run, and a call still pending when a turn stops or fails reads as stopped, since it may have run. The Runtime tab counts a call that never ran as a finished step instead of one still waiting.
- A message that waits for an automatic context compaction shows as being sent under a Compacting context row, and stays in its thread's queue through a reload, another thread or a closed window.
- A command that keeps streaming output after its turn no longer redraws the conversation with each piece of output.
- The composer and the model picker follow a Settings change that makes the harness ready or not, such as a sign-in, a key saved or removed or an install, at once, without a reload.
- A harness's own slash commands and agents, such as Claude Code's and OpenCode's, show in a new chat's / menu and agent picker as soon as the window opens.
- Settings' MCP servers card names the harness whose sessions get the servers.

## Interface

- **The first screen loads less.** What you start around a turn or past a thread's first page now loads right after the window first draws: background and two-model sends, Send now, Edit from here, Compact, a desktop SnapShot, Load earlier messages, the find bar, History's pages, the sidebar's search, Cite and linked threads. Use one before it has loaded and it happens once, as soon as it arrives; if it cannot load, Trebell says that part of Trebell could not load and keeps your draft or follow-up.
- The command palette lists every command before you type, Settings and Copy conversation among them in the desktop app. When message search cannot load, its notice and Reload stay in place while you type.
- A page, right panel tab, card or dialog that cannot load says so in plain words with Reload, instead of a browser error, and Usage, Tools and Environments keep their heading above it.
- One press of Ctrl+Shift+M or of the model picker's button shows the picker in view over the terminal drawer. One Shift+Tab from the draft with the / or @ menu open leaves the composer. Settings' Check again, the desktop app's Check now and Usage's Refresh keep the keyboard while they work.
- In Settings, harness rows keep their buttons beside their badge, fit at a phone's width and show whole when the keyboard reaches them, commands Trebell asks you to run show as code, and a refused theme save is said once, under the theme buttons. A harness update that ended during a reload says how it went when Settings opens again, and Antigravity's sign-in answer shows even if you left Settings meanwhile.
- The Git tab draws changed paths whole at every zoom, the Execution trace's Warning chip stands out in the app's warning tone, and the composer above the terminal drawer no longer shimmers at 125% display scaling.

## Other

- Source control writes a pull request's title and description also for a branch whose changes are larger than the 4 MB of diff it reads, from the part it read, instead of failing.
- Settings, Open source licenses shows the full notice of saxes, the XML reader that document text extraction uses, and the license files of Codex, the OpenCode SDK and the OpenCode client.

## Install and update

- Windows x64: download and run `Trebell-Code-Setup-2.1.0.exe` from the releases repository, https://github.com/tanishqbaweja/trebellcode-releases.
- If you have 2.0.0 or 2.0.1, the in-app updater offers 2.1.0; it downloads and installs only when you choose to.
- The installer is not signed, so Windows SmartScreen may ask you to confirm it before it runs (More info, then Run anyway).
