# Trebell Code 1.6.0

Version 1.6.0 is the first major Trebell Code release since 1.3.6. The release centers the product on its core goal: **produce the same or better verified software-engineering result at lower model cost**.

Since v1.3.6, the repository has accumulated hundreds of implementation and validation changes across Trebell Native, provider execution, verification/recovery, benchmark infrastructure, desktop reliability, and the public product surface.

## Quality per dollar

- Trebell Native now treats verifier quality and total model cost as first-class outcome metrics rather than optimizing raw token count in isolation.
- Context growth, prompt-cache continuity, tool exposure, recovery loops, output volume, and unnecessary model turns are measured as harness-level cost surfaces.
- Public comparisons use the same task/model/reasoning configuration where the benchmark supports it, with independent verification and API-equivalent cost accounting.
- The public [benchmark results](../../BENCHMARKS.md) include full-quality and equal-outcome cases where Trebell Native reaches the same verifier result with lower model spend or substantially lower model traffic.

## Trebell Native harness

- Added semantic completion gates that require evidence before a task is treated as complete.
- Added bounded semantic recovery for failed acceptance, explicit verification gaps, incomplete required deliverables, and recoverable pre-edit blockers.
- Added incumbent preservation and transactional rollback so recovery can restore a stronger evidence-backed candidate instead of blindly continuing from a regression.
- Added recovery-aware evidence budgets, revision-churn pressure, post-edit convergence controls, and bounded terminal/tool settlement.
- Added context/control-message compaction for completion gates while preserving the real action-turn conversation and continuation/cache history.
- Added richer Native strategy and request metrics for turns, tools, cache behavior, reasoning/output concentration, recovery epochs, and verifier-oriented completion behavior.

## Provider and model execution

- Hardened OpenAI Responses WebSocket continuation, deadlines, retry classification, cancellation, reconnect handling, and stale continuation-parent expiry.
- Added explicit reasoning-effort and service-tier plumbing for providers that support those controls, including OpenAI Fast-tier benchmark parity.
- Improved Anthropic-compatible message handling and provider capability routing.
- Reduced hidden reasoning carryover where it inflated billed context without improving the visible task state.
- Added strict structured output for Native control gates on OpenAI and stronger malformed/empty gate handling.

## Verification and engineering tools

- Verification now treats quantitative targets, persistent deliverables, structured-artifact invariants, public interface compatibility, and acceptance-critical runtime branches as explicit evidence surfaces.
- Native can preserve and replay more tool evidence without repeatedly paying to rediscover the same state.
- Process-tree cleanup, foreground terminal settlement, background-process handling, and environment teardown were hardened for long-running agent tasks.
- Browser and desktop automation cleanup was strengthened to avoid leaked Electron/browser processes during automated validation.

## Benchmark infrastructure

- Added the current Terminal-Bench/Harbor comparison path for Trebell Native, Codex API, and Codex OAuth.
- Added same-model reasoning/service-tier controls, hosted-web-search parity, per-lane cost accounting, cache metrics, task provenance, verifier summaries, and payload-safe live health monitoring.
- Added detached/headless Windows launch support, parallel-lane execution, Docker/task-cache prewarming, process drain checks, transport recovery, and dirty-source preflight protection.
- Benchmark evidence now distinguishes setup/infrastructure failures from model-quality results instead of collapsing both into the same score.

## Desktop and product surface

- Improved desktop/browser lifecycle reliability and hidden/headless validation behavior.
- Continued provider/runtime capability detection so unavailable features fail honestly instead of surfacing fake parity controls.
- Reorganized the public repository around Trebell's quality-per-dollar product thesis, concise product documentation, security reporting, and verifier-grounded benchmark results.

## Benchmark evidence

Current public results include:

- `coq-block-bound`: Trebell Native and Codex API both passed **4/4** with reward **1.0**; Native's API-equivalent cost was **28.6% lower**.
- `ctr-optimization`: all three lanes reached the same **3/4** verifier outcome and failed the same core threshold; Native cost **80.5% less than Codex OAuth** and **90.7% less than Codex API**.
- Additional causal diagnostics show equal verifier quality with substantially lower model traffic on already-inspected tasks; those are labeled separately in the benchmark page.

These are task-level measurements, not a claim that every workload is cheaper. The release goal remains to expand the set of workloads where Trebell reaches equal-or-better quality for less total spend.
